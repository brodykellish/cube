@src/cube/dag/dag.py and @src/cube/render/dag_renderer.py have some bad overlapping responsibility. I want the @src/cube/dag/dag.py to handle tracking the connections between nodes - that is, i want the @src/cube/dag/dag.py to determine what output textures are connected to what input textures, across source and effect nodes. I also want the DAG to encode information about (eventual) feedback connections between nodes (that is, if the output of a node should be used to feed back in as an input texture for e.g. accumulated state computation). When we go to render a DAG, the @src/cube/render/dag_renderer.py can handle all of the openGL calls required to actually load textures and allocate things, but the actual structure is fully encoded in the DAG. Some things to note:

1. Nodes (@src/cube/dag/effect_node.py  and @src/cube/dag/source_node.py ) can have variable number of input channels, some of which come from external sources (images, webcam frames, etc) and some of which might be feedback loops (e.g. the output texture of Node A is fed back to an input channel on Node A, and also passed down the chain to Node B)
2. I will eventually build a GUI that allows for direct manipulation of the DAG, so we can live remap inputs and outputs and add/remove nodes to the graph
3. the input/feedback configuration should be determined by the actual Shader program that a node is running. We need a way to discover the input dependencies (textures, feedback, etc) from the shader definition. We could either parse the shader .glsl file or write a config file.
4. we will have a few different sources of external data - this could be video frames from a video file, still image files, or a webcam video source.
5. I want to be able to iteratively build a DAG in the GUI, and then 'deploy' it all at once, at which point we send the updated DAG to the @src/cube/render/dag_renderer.py for rendering

Can you architect this system? In general, I want @src/cube/dag/dag.py to handle all connection logic, addition/removal of nodes, remapping of input/output dependencies, etc. I want @src/cube/render/dag_renderer.py to be a "dumb" (stateless) utility that crawls the DAG, orchestrating the OpenGL primitives required to render the full DAG pipeline.
